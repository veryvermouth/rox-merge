# rox-merge — 설계/계획 문서

Araxis Merge 류의 파일·폴더 비교/병합 도구. 본 문서는 구현 착수 전 합의를 위한 계획서다.

- 문서 버전: 0.4
- 작성일: 2026-06-28 (최종 수정: 2026-06-28)
- 상태: 주요 결정 완료 + 일관성 점검 반영 — 구현 착수 가능

---

## 1. 목표 / 비목표

### 1.1 목표
- 두 텍스트 파일을 나란히(side-by-side) 비교하고, 한 방향으로 변경분을 병합할 수 있는 GUI 도구.
- 파일을 선택하지 않아도 빈 편집기로 시작해 자유롭게 편집/저장 가능.
- 두 폴더를 비교해 어떤 파일이 추가/삭제/변경/동일한지 한눈에 파악.
- 단순 라인 diff를 넘어, **함수/블록 단위의 위치 이동(moved block)** 을 인지해 더 읽기 좋은 결과 제공.

### 1.2 비목표 (이번 범위 밖)
- 3-way 병합 / 충돌 자동 해결 (단, 데이터 모델은 확장 가능하게 설계).
- 이미지 / 바이너리(hex) 비교.
- 폴더 **동기화(파일 복사/삭제 실행)** — 이번엔 비교/표시까지만, 동기화 실행은 후속.
- VCS(git difftool/mergetool) 연동 — 후속 마일스톤.
- 실시간 협업 / 네트워크 기능.

## 2. 기능 범위 (MVP)

### M1. 2-way 텍스트 비교 + 병합 (핵심)
- 좌/우 두 파일을 열어 나란히 표시.
- 라인 단위 diff + 라인 내 **단어 단위 하이라이트**.
- **빈 파일 상태 편집**: 파일 미선택 시 빈 버퍼로 시작, 편집·저장(다른 이름으로 저장 포함) 가능. 한쪽만 열고 다른 쪽은 빈 상태로 두는 것도 허용한다. 단, **diff 계산/표시는 양쪽 모두 내용이 있을 때만** 동작한다(아래 4.6 참조). 한쪽이 비어 있는 동안에는 diff 색상·하이라이트 없이 양쪽 모두 플레인 텍스트로 보여준다.
- **한 방향 병합**: 각 diff 블록을 반대편으로 적용 (좌→우, 우→좌). 적용 후 diff 즉시 갱신.
- 양쪽 텍스트 직접 편집 가능, Undo/Redo 지원.

### M2. 폴더 비교
- 두 디렉터리를 재귀적으로 비교.
- 각 항목 상태 분류: `동일 / 좌측만 존재 / 우측만 존재 / 내용 다름`.
- **"내용 다름" 판정**: 기본은 빠른 비교(크기+mtime), 옵션으로 해시 정확 비교. 크기가 다르면 즉시 "다름", 크기 같고 mtime만 다르면(또는 정확 모드) 해시로 확인.
- 트리 형태로 표시, 항목 더블클릭 시 해당 파일 쌍을 M1 비교 뷰로 오픈.
- (비목표) 실제 복사/삭제 동기화는 제외.

> MVP 완료 기준: M1으로 두 파일을 비교·편집·단방향 병합·저장할 수 있고, M2로 폴더 차이를 트리로 보고 파일 비교로 진입할 수 있다.

## 3. 아키텍처 개요

UI와 엔진을 철저히 분리해, 프런트엔드 교체나 테스트가 쉽도록 한다.

```
+-------------------------------------------------------------+
|                      UI Layer (PySide6)                     |
|   - DiffView (side-by-side, 스크롤 동기화, 미니맵)          |
|   - FolderCompareView (트리)                                |
|   - 병합 버튼(→/←), 단축키, 색상 테마                       |
+----------------------------↓--------------------------------+
|                     Application Layer                        |
|   - 세션/문서 관리, 명령(Command) + Undo/Redo                |
|   - 병합 액션, diff 재계산 트리거                            |
+----------------------------↓--------------------------------+
|                       Core / Engine                         |
|   - Diff Engine (Myers + moved-block 탐지)                   |
|   - 라인/단어 토크나이저                                     |
|   - 비교 결과 모델 (DiffResult, Hunk, Alignment)            |
|   - 폴더 비교 엔진                                           |
+----------------------------↓--------------------------------+
|                    I/O & Platform Layer                      |
|   - 파일 읽기/쓰기, 인코딩 감지, 줄바꿈 처리                 |
|   - 파일시스템 탐색, 바이너리 감지                           |
+-------------------------------------------------------------+
```

핵심 원칙:
- **Core는 UI/Qt에 의존하지 않는다** (순수 Python). → 단위 테스트 용이.
- UI는 Core가 만든 `DiffResult`를 렌더링만 한다.
- 편집/병합은 모두 Command 객체를 거쳐 Undo/Redo 스택에 쌓인다.

## 4. Diff 엔진 설계

### 4.1 기본 알고리즘
- **Myers diff** 를 기본 라인 단위 diff로 사용 (최소 편집 거리 기반).
- 출력은 편집 스크립트(equal / insert / delete / replace 구간) 형태.

### 4.2 2단계 diff (단어 단위 하이라이트)
1. 1차: 라인 단위 Myers diff → equal/insert/delete/replace 블록.
2. 2차: `replace` 블록 내 대응되는 라인 쌍에 대해 **단어/토큰 단위 Myers diff** 재실행 → 라인 안에서 바뀐 부분만 하이라이트.
   - 토큰 단위: 공백/식별자/기호 기준 토크나이즈(언어 무관 기본 규칙).

### 4.3 이동(moved block) 탐지
함수 전체가 위치만 바뀐 경우를 "삭제+추가"가 아니라 "이동"으로 인지한다.

- 접근:
  1. 1차 Myers diff로 순수 삭제 라인 집합 D, 순수 추가 라인 집합 A를 구한다.
  2. D와 A 사이에서 **연속 라인 블록의 일치(부분 수열 매칭)** 를 찾는다. 해시 기반(라인 정규화 후 해시)으로 후보를 좁히고, 최소 블록 길이(예: 3라인 이상) 임계값을 둬 우연한 매칭을 배제.
  3. 매칭된 블록은 `moved` 상태로 별도 표시(전용 색상), 양쪽에서 연결선/배지로 연결.
- 옵션: 이동 탐지 on/off, 최소 블록 길이, 공백/대소문자 무시.
  - **기본값: 최소 블록 길이 3라인, 이동 탐지 기본 ON.**
- 주의: moved 탐지는 비용이 크므로 후보 제한·해시 인덱스로 성능 관리. 큰 파일에서는 임계값/상한으로 제한.

### 4.4 비교 옵션
- 공백 무시(전체/선행·후행/연속 공백 축약), 대소문자 무시, 빈 줄 무시.
- 줄바꿈 차이 무시.
- **기본 공백 처리 정책**: 위 "공백 무시" 옵션은 **기본 OFF**(공백을 구분)지만, **공백/들여쓰기만 다른 라인은 일반 change가 아니라 별도 종류 `whitespace`로 분류**해 약한(옅은) 색으로 표시한다.
  - 즉 어떤 함수 블록의 모든 라인에 탭 하나가 추가된 경우 → 각 라인은 `change`(짙은 강조)가 아니라 `whitespace`(옅은 강조)로 떠서, 실제 내용 변경과 시각적으로 구분된다.
  - "선행 공백 무시" 등 공백 무시 옵션을 켜면 `whitespace` 라인은 `equal`로 승격되어 아예 표시되지 않는다.
  - 판정: 두 라인을 공백 정규화했을 때 동일하면(=내용은 같고 공백만 다름) `whitespace`, 그 외 내용이 다르면 `change`.
  - **병합 대상**: `whitespace` 라인도 hunk로 묶여 `→/←` 병합 버튼이 표시되며, 다른 종류와 동일하게 단방향 병합할 수 있다(들여쓰기 통일 등을 한 방향으로 적용 가능).

### 4.5 정렬(Alignment) 모델
- side-by-side 표시를 위해, 좌/우 라인을 행 단위로 정렬한 **Alignment** 리스트를 생성.
- 각 정렬 행: `(left_line | None, right_line | None, kind)` 형태.
  - `kind ∈ {equal, change, whitespace, insert, delete, moved}`.
  - `whitespace`: 내용은 같고 공백/들여쓰기만 다른 라인(약한 색으로 표시, 4.4 참조).
  - 한쪽이 `None`이면 그쪽에 **gap(빈 줄)** 을 삽입해 시각적 정렬을 맞춘다.

### 4.6 증분 재계산
- **선행 조건(양쪽 텍스트 존재)**: diff 계산은 **좌·우 양쪽 버퍼가 모두 비어 있지 않을 때만** 수행한다.
  - 한쪽이라도 비어 있으면 diff를 돌리지 않고, 양쪽 모두 색상/단어 하이라이트 없는 **플레인 텍스트**로 표시한다(전체를 insert/delete로 칠하지 않는다).
  - 비어 있던 쪽에 내용이 채워져 양쪽 다 비지 않게 되는 순간부터 아래의 재계산 흐름이 시작된다.
- 위 조건을 만족하는 동안, 사용자가 한쪽을 편집하거나 병합하면 diff를 다시 계산.
- MVP: 단순 전체 재계산(파일이 아주 크지 않은 한 충분). debounce(예: 입력 후 150ms)로 과도한 재계산 방지.
- 후속: 변경된 영역 주변만 부분 재계산.

## 5. 데이터 모델

```text
Document
  path: str | None            # None이면 빈 새 버퍼
  encoding: str               # 감지된 인코딩
  line_ending: 'LF'|'CRLF'|'CR'
  lines: list[str]
  dirty: bool                 # 미저장 변경 여부

DiffResult
  alignment: list[Row]
  hunks: list[Hunk]           # 연속된 변경 묶음 (점프/병합 단위)
  moves: list[MovePair]       # 이동 블록 연결 정보

Row
  left_index: int | None
  right_index: int | None
  kind: equal|change|whitespace|insert|delete|moved
  intraline: list[Span] | None   # 단어 단위 하이라이트 구간

Hunk
  left_range, right_range
  kind
  id                          # 병합/점프 시 참조

MovePair
  left_block_range, right_block_range
```

병합/편집은 `Command`(apply/undo 보유)로 표현:
- `ApplyHunkCommand(direction, hunk_id)`
- `EditTextCommand(side, position, old, new)`

## 6. UI / UX 명세

### 6.1 전체 화면 구성
- 탭 또는 창 단위로 "비교 세션"을 가진다.
- 두 가지 주요 뷰: **파일 비교 뷰(M1)**, **폴더 비교 뷰(M2)**.

### 6.2 파일 비교 뷰 (side-by-side)
- 좌/우 두 개의 텍스트 에디터(편집 가능).
- **스크롤 동기화**: 정렬(Alignment) 기반으로 양쪽이 같이 스크롤. 한쪽에만 있는 라인은 반대편에 gap(빈 줄)으로 채워 행을 맞춘다.
- **변경 블록 점프 단축키**:
  - `Ctrl+1` → 이전 차이로 이동
  - `Ctrl+2` → 다음 차이로 이동
  - (현재 diff 블록을 화면 중앙으로 스크롤하며 하이라이트)
  - **경계 동작(clamp)**: 첫 번째 차이에서 `Ctrl+1`을 누르면 순환하지 않고 첫 차이에 그대로 머문다. 마찬가지로 마지막 차이에서 `Ctrl+2`도 제자리에 머문다(맨 처음/끝으로 wrap 하지 않음).
- **병합 액션 버튼**: 각 diff 블록의 안쪽 가장자리에 인라인 버튼 배치.
  - 왼쪽 창에서는 `→` (이 블록을 오른쪽에 적용)
  - 오른쪽 창에서는 `←` (이 블록을 왼쪽에 적용)
  - 버튼은 해당 블록 행에 정렬되어 표시.
- **파일 열기/닫기 단축키**:
  - `Ctrl+O` → 현재 포커스가 있는 쪽(좌/우) 에디터에 파일 열기 다이얼로그로 파일을 연다. 해당 쪽이 dirty면 열기 전에 6.5의 경고를 띄운다.
  - `Ctrl+W` → 현재 비교 탭(세션)을 닫는다. dirty 버퍼가 있으면 닫기 전에 경고(6.5).
- **저장 단축키**:
  - `Ctrl+S` → **현재 커서가 활성화된 쪽(좌 또는 우) 파일을 저장**한다. (포커스를 가진 에디터가 대상)
  - 해당 버퍼에 경로가 있으면(`path != None`) 그 경로에 덮어쓰기 저장(원본 인코딩·줄바꿈 유지, 7장 참조).
  - 해당 버퍼가 **빈/새 버퍼(`path == None`)** 이면 **다른 이름으로 저장(Save As)** 다이얼로그를 띄워 경로를 지정하고 저장한다.
  - 저장 성공 시 해당 쪽 `dirty` 플래그 해제.
  - `Ctrl+Shift+S` → 현재 활성 쪽을 **다른 이름으로 저장(Save As)** (경로 유무와 무관하게 새 경로 지정).
- **Undo / Redo 단축키**:
  - `Ctrl+Z` → 실행 취소(undo)
  - `Ctrl+Shift+Z` → 다시 실행(redo). 보조 키로 `Ctrl+Y`도 동일하게 redo.
  - **통합 스택**: 직접 타이핑 편집(`EditTextCommand`)과 병합 버튼(`ApplyHunkCommand`)은 **하나의 통합 Undo/Redo 스택**을 공유한다. 따라서 병합 버튼을 누른 직후 `Ctrl+Z`를 누르면 그 병합이 취소되고, `Ctrl+Shift+Z`로 다시 적용된다. (직전 동작이 편집이든 병합이든 동일하게 한 단계씩 되돌리고/다시 적용)
  - undo/redo 후에는 diff를 재계산해 UI를 갱신한다(4.6).
- **글꼴 확대/축소 단축키**:
  - `Ctrl++` → 에디터 글꼴 확대(zoom in). 대다수 키보드에서 실제 입력은 `Ctrl+Shift+=`이므로 **`Ctrl+=`도 동등하게 바인딩**한다.
  - `Ctrl+-` → 에디터 글꼴 축소(zoom out)
  - `Ctrl+0` → 글꼴 배율 100%로 리셋 (포커스가 에디터에 있을 때)
  - (좌/우 에디터에 동일 배율 적용)
  - **`Ctrl+0` 포커스 분기**: 분할 모드처럼 트리와 에디터가 한 화면에 있을 때, `Ctrl+0`은 **현재 포커스 위치**로 동작을 정한다 — 에디터에 포커스면 글꼴 리셋, 폴더 트리에 포커스면 트리 초기 확장 리셋(6.4).
- **미니맵 / 오버뷰 바**: 양쪽 에디터 옆 세로 바에 전체 파일 대비 변경 위치를 색상으로 축소 표시, 클릭 시 해당 위치로 점프.
- 상단 툴바: 열기(좌/우), 저장, 다른 이름으로 저장, Undo/Redo, 비교 옵션(공백/대소문자 무시 등), 이동 탐지 토글, 이전/다음 차이, 글꼴 확대/축소.

### 6.3 색상 규칙
| 종류 | 의미 | 예시 색상(테마에서 조정) |
|---|---|---|
| equal | 동일 | 배경색(없음) |
| insert(추가) | 한쪽에만 추가됨 | 초록 계열 |
| delete(삭제) | 한쪽에서 삭제됨 | 빨강 계열 |
| change(변경) | 양쪽 대응되나 내용 다름 | 노랑/파랑 계열 + 단어단위 강조 |
| whitespace(공백만) | 내용 같고 공백/들여쓰기만 다름 | change보다 **옅은** 색(약한 강조) |
| moved(이동) | 블록 위치 이동 | 보라/청록 계열 + 연결 표시 |
| conflict(충돌) | (후속 3-way용 예약 — **현재 MVP에서는 미사용**, `kind` 열거에 없음) | 주황/강조 |

- 라인 배경색(블록 종류) + 라인 내 단어 강조색(intraline)을 구분.
- 라이트/다크 테마 모두 고려, 색은 테마 토큰으로 분리.

### 6.4 폴더 비교 뷰
- 좌/우 폴더 경로 선택.
- **상단 툴바**: 좌/우 폴더 열기·새로고침, 필터(다른 항목만 보기), 전체 펼치기/접기, **여는 방식 토글(분할 모드 ↔ 새 탭 모드)**, 비교 정밀도 토글(빠른 비교 ↔ 해시 정확 비교).
- 트리(또는 2-pane 트리)로 항목 나열, 상태별 색상/아이콘.
- **트리 초기 확장 상태**: 처음 열 때 **차이가 있는 경로만 자동으로 펼치고**(하위에 추가/삭제/내용 다름 항목이 있는 폴더), 동일한 가지는 접어 둔다. → 개요를 보면서도 바뀐 부분으로 바로 진입.
- **펼치기/접기 단축키**:
  - `Ctrl+]` → 트리 전체 펼침(expand all)
  - `Ctrl+[` → 트리 전체 접기(collapse all)
  - `Ctrl+0` → 초기 상태로 복귀(차이 있는 경로만 펼친 기본 상태로 리셋) — **트리에 포커스가 있을 때**. (에디터 포커스 시에는 글꼴 리셋으로 동작, 6.2 참조)
  - (개별 노드는 클릭/방향키 등 표준 트리 조작으로 펼침·접힘)
- 필터: "다른 항목만 보기", 동일 항목 숨기기.
- **항목 더블클릭 → 파일 비교 뷰로 오픈.** 여는 방식은 두 가지 모드를 지원하며, **툴바의 토글 버튼**으로 전환한다:
  - **분할 모드(기본)**: 폴더 비교 화면을 상/하로 분할한다. 위쪽에는 폴더 비교 트리, 아래쪽에는 더블클릭한 파일의 파일 비교(diff) 뷰가 표시된다. 이 상태에서 트리의 다른 파일을 더블클릭하면 **아래쪽 창만** 새로 더블클릭한 파일의 비교 뷰로 교체된다(분할은 유지, 위쪽 트리 그대로). 단, 아래쪽 창에 **미저장 변경(dirty)** 이 있으면 곧바로 교체하지 않고 **2지선다 경고**를 띄운다:
    - **현재 창 유지(취소)**: 교체하지 않고 편집 중이던 현재 파일 비교로 되돌아간다(더블클릭 무시).
    - **무시하고 열기**: 편집분을 저장하지 않고 버린 뒤, 더블클릭한 파일로 아래쪽 창을 교체한다.
    - (이 흐름에는 "저장 후 이동" 선택지를 두지 않는다.)
  - **새 탭 모드**: 파일을 더블클릭할 때마다 **새 비교 탭**을 생성해 연다(여러 파일을 동시에 열어두고 탭 간 이동). 6.1의 탭 단위 비교 세션과 연결.
  - 툴바 토글 버튼으로 두 모드를 오갈 수 있다. (기본값은 분할 모드)

### 6.5 빈 파일/새 버퍼 UX
- 시작 시 또는 메뉴에서 "빈 비교" 생성 → 양쪽 또는 한쪽이 빈 버퍼.
- 빈 버퍼도 정상 편집/저장 대상. 저장 시 경로 지정(다른 이름으로 저장).
- **한쪽이 비어 있는 동안에는 diff를 표시하지 않고 양쪽을 플레인 텍스트로 보여준다.** 양쪽 모두 내용이 채워지면 그때부터 diff 갱신(4.6)이 동작한다.
- 미저장 변경(dirty) 시 닫기/덮어쓰기 전에 경고.

### 6.6 단축키 일람

| 단축키 | 동작 | 범위 |
|---|---|---|
| `Ctrl+O` | 활성(포커스) 쪽 에디터에 파일 열기 | 파일 비교 뷰 |
| `Ctrl+W` | 현재 비교 탭(세션) 닫기 | 공통 |
| `Ctrl+S` | 활성(포커스) 쪽 파일 저장. 빈/새 버퍼면 다른 이름으로 저장 | 파일 비교 뷰 |

| `Ctrl+Z` | 실행 취소(undo) — 편집·병합 통합 스택 | 파일 비교 뷰 |

> 병합은 각 diff 블록의 인라인 버튼(`→`/`←`)으로 수행(단축키 미할당, 6.2).

## 7. 파일 / 인코딩 처리

- **인코딩 감지**: UTF-8(BOM 포함/미포함), UTF-16, 시스템 기본(Windows의 경우 cp949/EUC-KR 가능성) 자동 감지. 감지 실패 시 사용자에게 인코딩 선택 제공. (라이브러리: `charset-normalizer` 등 검토.)
- **줄바꿈**: LF/CRLF/CR 감지 후 보존. 혼합 시 표시 및 정규화 옵션.
- **바이너리 감지**: NUL 바이트 등으로 판별, 바이너리면 텍스트 diff 거부하고 "바이너리 파일 - 비교 불가" 표시.
- **큰 파일**: 일정 크기 초과 시 경고 및 제한(예: diff 라인 상한, moved 탐지 비활성). 후속에서 청크/지연 로딩.
- 저장 시 원본 인코딩·줄바꿈 유지(사용자가 바꾸지 않는 한).
- 외부에서 파일이 변경되면 감지해 새로고침 제안(후속).

## 8. 비기능 요구사항

- **성능 목표(초안)**: 1만 라인 파일 쌍 비교/렌더 < 0.5s, 5만 라인 < 2s. moved 탐지 포함 시 상한 적용.
- **테스트 전략**:
  - Core(diff/alignment/moved/폴더비교)는 **순수 Python 단위 테스트**로 커버. 골든 케이스 + 엣지 케이스(빈 파일, 한쪽만 존재, 동일 파일, 전부 변경, 큰 이동 블록, 공백만 차이).
  - 인코딩/줄바꿈 처리 별도 테스트.
  - UI는 핵심 로직(정렬→렌더 매핑, 단축키, 병합 커맨드)을 가능한 한 모델 단으로 내려 테스트.
- **플랫폼**: 1차 Windows. PySide6 사용 시 macOS/Linux 동작도 가능(추후 확인).
- **확장성**: diff 알고리즘, syntax highlighter, VCS 연동을 인터페이스로 분리해 후속 추가 용이.

| 항목 | 선택(제안) | 비고 / 대안 |
|---|---|---|

| 테스트 | pytest | |

> ✅ **결정됨**: GUI 프레임워크는 **PySide6 (Qt)** 로 확정.
> 근거: 이 앱의 핵심 화면(side-by-side, 라인/단어 하이라이트, gap, 미니맵)은 표준 네이티브 위젯이 아니라 **직접 그리는 커스텀 텍스트 뷰**라, 네이티브 위젯 래핑의 이점이 작다. 정작 중요한 커스텀 렌더링·텍스트 레이아웃·대용량 가상 스크롤 성능에서 Qt가 최상위권이고, 순수 Python Core를 그대로 재사용할 수 있다. 완전한 Windows 네이티브 룩앤필/최소 배포 크기가 최우선이라면 WinUI 3/WPF(.NET)가 대안이나, Python Core 분리 비용이 커서 이번엔 채택하지 않음.
